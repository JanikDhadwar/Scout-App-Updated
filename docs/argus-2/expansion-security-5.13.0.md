# Argus 5.13.0 security reassessment

Reviewed 2026-10-28 against main b47679f plus this uncommitted update. This is a bounded source review and isolated-fixture verification, not a production penetration test or security certification. No real database, private integration file, production session, or public-server exploit traffic was used.

## Findings and dispositions

| ID / classification | Severity | Evidence | Disposition and regression |
| --- | --- | --- | --- |
| E01 Confirmed vulnerability: session persistence amplification | Medium availability | server.cjs session middleware calls private-sessions.cjs delete for unknown cookies; old delete always saved synchronously. A temporary fixture reproduced two writes for two unknown tokens. | Fixed: absent deletion returns false without a write. expansion-security.test.cjs verifies no file creation/changes and durable real revocation. expansion-api.test.cjs verifies three unauthenticated HTTP requests with unknown cookies cause no session-file modification. No production exhaustion impact is claimed. |
| E02 Confirmed validation gap; resource-exhaustion impact remained potential | Medium | media-validation.cjs previously returned 1x1 for every accepted VP8/VP8L container, bypassing dimension/pixel budgets. | Fixed: parse actual lossy/lossless dimensions, signatures, chunk bounds and lossless version. Synthetic tests include valid Pillow-generated 2x3 files, oversized dimensions, pixel limits, truncated and malformed headers. Existing stored reports are not rewritten. Codec preflight is not a complete decoder or an exploit demonstration. |
| E03 Security improvement: bounded aggregate resources | Medium preventive priority | New analytics could retain raw media/report duplication or repeatedly recompute per viewer; exports can be large. | Cache source references/derived measurements, exclude media bodies from aggregate observations, share results only under equivalent authorization scopes, cap 32 entries/32 MiB total/16 MiB per entry, expire after 30 seconds and clear after confirmed database writes. Export in a worker, cap team count, terminate on cancel/unmount, reject late messages before download. Benchmark uses 100 teams, 200 matches, 6000 synthetic reports. |
| E04 Security improvement: stale authorization in presentation memory | Medium preventive priority | Frozen presentations must not outlive confirmed user/workspace/role/sharing changes. | Scope presentation keys by identity/workspace/event/role/sharing; remount workspace after confirmed role changes, invalidate read caches first and terminate old exports. Existing queued reports and drafts are retained. Already downloaded files/offline copies cannot be remotely erased. |
| E05 Security improvement: external forecast handling | Low/medium preventive priority | Predictions formerly acquired a new retrieval time on cache hits; stale client retention lacked ordered-alliance binding. Upstream JSON and quotas need bounds. | Preserve true upstream retrieval time, bind original official ordered alliances, scope device caches, clear on unauthorized responses, label cached/stale estimates. Cap provider bodies at 2 MiB, coalesce calls, respect known exhausted quota windows and Retry-After up to the provider's weekly window. Participant-only payloads still cannot independently prove provider color assignment. |
| E06 Potential vulnerability if legacy credentials remain | Medium conditional | password-service.cjs retains legacy hash verification for account compatibility; successful login upgrades to salted asynchronous scrypt. Real credential formats were not inspected. | Preserve accounts and existing migration. Operator may privately assess dormant legacy accounts and recovery arrangements. Do not export hashes, force resets, or claim the real database contains weak hashes based on synthetic fixtures. |
| E07 Dependency advisory in build tooling | Low, observed | npm audit reported four low affected packages tracing to deepmerge, through @rollup/plugin-node-resolve → workbox-build → vite-plugin-pwa. npm audit --omit=dev reported zero vulnerabilities. | Recorded, not silently force-fixed: npm suggested downgrading vite-plugin-pwa to 0.2.1, a breaking/inappropriate automatic change. No application runtime dependency changes were introduced. Track a compatible upstream fix and retest PWA/build/notices before changing versions. |
| E08 Previously resolved controls | Informational | Current password-service.cjs, auth-limits.cjs, server.cjs, mfa-service.cjs, writer-lock.cjs and existing suites. | Bounded async scrypt, bounded auth/join throttles, HttpOnly/SameSite/Secure cookie configuration, origin checks, CSP/security headers, MFA/recovery, atomic DB replacement and single-writer locking remain. Historical documents describing their earlier absence are not current open vulnerabilities. |

Primary format references used for E02: [WebP container specification](https://developers.google.com/speed/webp/docs/riff_container), [WebP lossless bitstream specification](https://developers.google.com/speed/webp/docs/webp_lossless_bitstream_specification).

## Trust boundaries reviewed

- Authentication/recovery/MFA: opaque server sessions, salted async hashing and legacy upgrade, single-use recovery, enrolled MFA login, optional privileged enforcement and revocation. New onboarding flags are private account metadata and never bypass authentication.
- Direct API authorization: owner/admin configuration, immutable report retry keys, cross-workspace analytics/evidence denial, approved structured member summaries, sharing/configuration revisions. Source links reuse the existing authorized evidence route. No public publishing or new role.
- Templates/forms: copies receive fresh IDs; ordinary server validation and permissions still apply. Hints/examples are bounded strings; numeric review comparisons reference earlier numeric questions. Historical versions and unknown snapshots preserve the existing review/quarantine boundary.
- Frontend input: React text rendering, no new raw HTML sink or execution of note/provider/training content. SVG illustrations are application code. Export snapshots omit identities/raw answers/media; notes need authorized opt-in.
- External services: only existing fixed Match13/TBA origins and private server keys. No additional provider, AI call, notes/photo upload, or scout identity transmission. Forecast status contains no keys.
- Offline: existing account/workspace scope and IndexedDB stores remain. Read-data clearing keeps drafts/queue/receipts; tests verify other accounts survive and stale privileged in-flight reads cannot restore old data. Offline access still depends on physical/device access controls.
- Storage/recovery: existing migration/durability/backup and writer-lock suites are retained. New fields are additive; rollback must not replace newer scouting records with an old database.
- Logs/secrets/release: existing safe request-ID logging and bounded secret/static scans remain. New fixture tests use explicit isolated environment files. Developer architecture was moved out of shipped Help into repository-only documentation.

## Operational requirements not established locally

Production Cloudflare zone/tunnel/cache/WAF settings, trusted proxy address derivation, TLS/Secure-cookie behavior, origin-port exposure, filesystem ACLs, MFA encryption-key backup, off-host encrypted backup scheduling/retention, actual restore drills, monitored alerts/responders, admission capacity and adopted privacy/retention procedures require operator evidence. No configuration or production change was made.

MFA remains optional as approved. Old downloaded/offline/exported material cannot be remotely erased after revocation. Native file-symlink creation is unavailable to this Windows account; the MFA symlink test is explicitly skipped here and still runs where that privilege exists. Other tested writer/database symlink guards and all non-skipped tests remain active.
