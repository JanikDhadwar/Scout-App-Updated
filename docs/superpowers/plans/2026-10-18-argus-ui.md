# Argus UI implementation plan

**Goal:** Refine the existing Team 6390 scouting app without changing report storage, permissions, or offline behavior.

**Architecture:** Keep the React 19 and Vite application in the current checkout so GitHub Desktop can commit and push it. Shared CSS defines the design tokens. Small shared UI components provide the team logo, icons, and accessible disclosures.

**Approved direction:** A dark graphite workspace with white text, restrained team red, the supplied logo, clear mobile controls, and short interaction-driven transitions.

## Design

- Canvas #101114, panels #191B20, raised controls #24272E, borders #353942, text #F5F6F8, action red #D93644. Secondary text #ADB3BE.
- Typography uses the platform sans family with tabular numerals for counts. Headings use deliberate size and weight rather than uppercase or decorative labels.
- Desktop keeps the sidebar and a compact header. Home prioritizes scouting forms beside competition information, with quieter report counts and team updates below. Phone layouts retain the five-item bottom navigation.
- The team logo anchors sign-in and navigation. No ornamental gradients, repeated red card borders, or numbered rows that imply an order.
- Motion answers actions: dropdown open and close, account disclosure expansion, control selection and focus. Reduced motion disables these transitions.

- [x] Run existing tests, production build, and lint. Review the diff and fix introduced issues.
- [ ] Commit all requested project changes and push with GitHub Desktop. Verify the pushed commit and report any limitation honestly.

## Review focus

Empty teams must have useful next actions. Long form and team names must wrap. Mobile menus must close with Escape and return focus. Closed disclosures must not retain keyboard focus. Offline reports and role-based navigation must continue working.

## Verification

The production build succeeds and all 16 existing tests pass. Browser checks with Edge cover 320, 375, 768, 844, and 1440 pixel widths, the mobile menu, Escape and outside-click dismissal, focus restoration, account disclosure keyboard exclusion, reduced motion, and sign-in validation. News, Event, Data, and Manage fit a 375 pixel viewport. No browser runtime errors occurred during these checks.

An isolated temporary database confirmed that a draft survives reload. A report submitted while offline remained saved and uploaded once after reconnecting. The real project database was not modified.

Source review found a long-team-name overflow in the header. The text now truncates within its flex container, and a 180-character name passed the 320 pixel layout check. Short desktop sidebars scroll so navigation stays reachable in landscape.

The repository-wide lint command still reports existing issues in legacy source and generated public service-worker files. Comparing the modified entry component against HEAD found no introduced lint diagnostics and one removed diagnostic. The other modified and new JavaScript UI files pass lint.
