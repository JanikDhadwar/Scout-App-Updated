# Argus UI implementation plan

**Goal:** Make the existing scouting app easier to read and use, without team logo branding or a marketing-style dashboard.

**Architecture:** Keep React 19, Vite, the existing navigation, and offline storage. Shared CSS controls layout and interaction states. Transitions.dev supplies the mobile dropdown and account disclosure motion.

## Current design

- Neutral graphite backgrounds with red primary actions, selected navigation, form selections, progress, and keyboard focus. The simplified layout and removal of team branding remain in place.
- A compact sidebar and header. The selected workspace name remains as account context, not a fixed team identity.
- Home uses a list of scouting forms, recent submissions, and team news. A narrow secondary column holds the current event and device status. Phone screens stack these sections above the bottom navigation.
- Forms use rows rather than repeated cards. The sign-in screen contains only the app name, account controls, and fields.
- No team logo, oversized team number, welcome slogan, statistic tiles, or decorative red card accents.
- Short control transitions, an anchored mobile menu, an expanding account disclosure, and reduced-motion support.

## Implementation

- [x] Remove the team logo component and asset, team-specific favicon, and fixed team identity in the install manifest and sign-in screen.
- [x] Replace the dashboard tile grid with content lists and useful recent reports.
- [x] Refine navigation, form lists, account controls, and mobile layouts.
- [x] Keep permissions, report storage, and sync behavior intact.
- [x] Verify production build, existing tests, responsive layouts, keyboard behavior, and offline reports.
- [ ] Commit changes and push through GitHub Desktop when available.

## Review focus

Long form and workspace names must fit. Form and report lists need useful empty states. Hidden account controls and menus must stay out of the tab order. Keyboard dismissal must return focus. Offline reports must remain saved after reload and upload once after reconnecting.

## Verification

The production build and all 16 existing tests pass. The edited shared UI components and Vite config pass targeted lint. Existing lint diagnostics in the legacy entry component and generated public files are outside this visual revision.

Edge checks passed at 320, 375, 768, 844, and 1440 pixel widths. Tests cover form lists, News, Event, Escape dismissal and focus return, hidden disclosure controls, reduced motion, a long unbroken report title, and accessible sign-in validation. No browser runtime errors occurred.

Using a temporary database, a report draft survived reload and an offline submission uploaded once after reconnection. The real project database was not modified. Review found the long-report-title overflow, which is fixed and browser-verified.
